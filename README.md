# NeoBoot — Ibrahem Hamdan | إبراهيم حمدان

**الإصدار: 10.0 — نسخة معدّلة تجريبية لأجهزة Enigma2 المدعومة.**

الاسم الظاهر في قائمة البلجن، عنوان الشاشة، بيانات التثبيت ورقم الإصدار يحمل اسم إبراهيم حمدان. ملفات التشغيل المرفقة تخص ARMv7 hard-float وMIPSEL ‏32 بت؛ لا تضيف هذه النسخة دعم ARM64 أو موديلات وكيرنلات جديدة. يلزم اختبار الإقلاع على جهاز حقيقي.

## الرفع على GitHub لأول مرة

1. أنشئ مستودعًا **Public** باسم تختاره، مثل `NeoBoot-Ibrahem-Hamdan`.
2. فك ضغط الحزمة وارفع **كل محتويات هذا المجلد** إلى جذر المستودع، بما فيها `.github/workflows/release.yml`. لا ترفع ZIP فقط.
3. افتح **Actions → Build and publish NeoBoot → Run workflow**.
4. عندما تنجح العملية سيظهر إصدار `v10.0` في **Releases**، ومعه IPK وملف التحديث `update.json` والبصمة `SHA256SUMS` وملف التثبيت `install.py`.
5. نزّل IPK من ذلك الإصدار؛ اسم المستودع سيُدمج داخله تلقائيًا. النسخة الموجودة في `dist` قبل الرفع غير مرتبطة بحساب محدد؛ يمكن ضبط حسابك من زر التحديث داخل البلجن بإدخال `OWNER/REPO` أو رابط المستودع.

ملف `REPOSITORY` اختياري للبناء على الكمبيوتر. اكتب فيه `OWNER/REPO` أو نفّذ:

```sh
python3 build.py --repository OWNER/REPO
```

لا تضع كلمات مرور أو توكنات في الملفات. يستخدم Workflow توكن GitHub الخاص به عند تشغيله. لا يتم النشر بمجرد رفع الملفات؛ النشر يحتاج تشغيل Workflow يدويًا.

## التحديثات اللاحقة

- عدّل المصدر ثم ارفع رقم `VERSION` إلى `10.1` مثلًا.
- شغّل Workflow مرة أخرى؛ يُحدّث الإصدار الداخلي وبيانات IPK وmetadata وعناوين الواجهة ونسخة العرض في قوائم الإقلاع تلقائيًا.
- كل رقم إصدار ينشر مرة واحدة؛ عند إعادة النشر ارفع الرقم بدل استبدال إصدار قائم.
- أرقام العرض الموجودة داخل ملفات ELF لها مساحة ثابتة؛ تُقبل حاليًا أرقام بطول `10.0` نفسه. إصدار بطول مختلف يحتاج إعادة بناء برامج القائمة الأصلية، والبناء يرفضه صراحةً.

## التثبيت

ضع `dist/NeoBoot-Ibrahem-Hamdan.ipk` في `/tmp` على الرسيفر:

```sh
opkg install /tmp/NeoBoot-Ibrahem-Hamdan.ipk
```

ثم أعد تشغيل واجهة Enigma2 يدويًا. اسم الحزمة الجديد:

```text
enigma2-plugin-extensions-neoboot-ibrahem-hamdan
```

مراجع LinuxSat المتبقية في `Replaces` و`Conflicts` مخصصة للتعرف على الحزمة القديمة أثناء الترقية فقط. لا تظهر كاسم النسخة الجديدة. إذا رفض مدير الحزم إزالة النسخة القديمة لأنها فعالة ضمن الإقلاع، عالج ذلك من واجهة نيوبوت على جهازك ولا تستخدم أوامر force لإخفاء الخطأ. ترحيل اسم الحزمة لم يُجرب على opkg حقيقي هنا.

بديل التثبيت من آخر إصدار منشور:

```sh
sh install.sh OWNER/REPO
```

يحتاج هذا الأمر نشر أول Release قبل تشغيله. التحديث داخل البلجن ينزّل الحزمة من مستودعك المحدد ويتحقق من SHA-256 ويعرض فشل opkg بدل إخفائه. لا يستخدم سكربت تحديث NeoBoot القديم ولا يمسح `/tmp` بالكامل.

## الاختبارات والحدود

```sh
python3 -m unittest discover -s tests -v
```

اجتازت النسخة 22 اختبارًا آليًا محليًا. الاختبارات محلية ومحاكاة؛ لا تثبت الإقلاع أو الريموت أو توافق جميع صور Enigma2. دعم Python 2 راجع نحويًا فقط، وLZO اختبر بمحاكاة الربط. ملف `docs/compatibility-audit-r11.txt` يسجل مراجعة الإصلاحات السابقة؛ هذه النسخة تضيف الاسم والإصدار والتحديث عبر GitHub. التعديلات على ملفات ELF تقتصر على استبدال نص الإصدار بنفس الطول، دون إضافة دعم لمعالج جديد.
